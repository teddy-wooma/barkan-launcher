# 모드 잠금 파일 (`app/assets/mods.lock.json`)

런처가 게임 `mods` 폴더에 넣는 jar 는 전부 런처 안에 고정된 목록과 SHA-512 로 검증합니다.

## 왜 바꿨나

1.0.20 까지 런처는 PLAY 때마다 `FISH_MOD_LIST` 저장소 `main` 브랜치의 `mods.json` 을 받아,
거기 적힌 jar 와 모드린스 «최신판» 을 해시 검사 없이 설치했습니다. 필수 모드는 바뀌면 자동으로
다시 받았습니다. 그래서 아래 중 하나만 털려도 런처를 쓰는 모든 유저 PC 에서 그 코드가 실행됩니다.

- `FISH_MOD_LIST` 를 쓸 수 있는 GitHub 계정·토큰
- 목록에 있는 모드린스 모드의 작성자 계정 (최신판을 자동으로 따라가므로)

2026-11 「승리의 여신: 니케」 PC 런처 사고(배포 서버의 파일이 바뀌자 런처가 그대로 받아 실행)와 같은 구조입니다.
마인크래프트에서도 2023년 Fractureiser(모드 배포 계정 탈취) 사례가 있습니다.

## 지금 동작

- 목록·버전·다운로드 주소·크기·SHA-512 는 `app/assets/mods.lock.json` 에 고정됩니다.
  - 모드린스: 버전 ID 가 들어간 `cdn.modrinth.com/data/<프로젝트>/versions/<버전>/…` 주소
  - GitHub jar: 브랜치가 아니라 **커밋 SHA** 주소 (`raw.githubusercontent.com/<소유자>/<저장소>/<커밋>/…`)
- 내려받은 파일은 `.part` 로 받은 뒤 크기·SHA-512 가 맞을 때만 제자리로 옮깁니다. 맞지 않으면 지우고 실패합니다.
- 이미 설치된 필수 모드의 내용이 잠금 파일과 다르면 검증된 파일로 바꿉니다. 선택 모드는 «업데이트» 버튼으로만 바꿉니다.
- 배포 인덱스(`distribution.json`)의 `clientMods`(Sodium·Iris)도 `sha512` 가 있어야 `mods` 폴더에 들어갑니다.
  셰이더팩에도 해시를 적어 두었습니다.

## 모드를 추가·업데이트하는 법

1. `FISH_MOD_LIST` 의 `mods.json` 을 예전처럼 고칩니다. (또는 로컬 파일을 준비합니다)
2. 런처 저장소에서 잠금 파일을 다시 만듭니다.

   ```bash
   npm run lock:mods                           # FISH_MOD_LIST main 기준
   npm run lock:mods -- --source ./mods.json   # 로컬 목록 기준
   npm run lock:mods -- --distribution         # Sodium·Iris·셰이더팩 해시도 다시 계산
   ```

   도구는 파일을 실제로 내려받아 해시를 재고, 모드린스가 알려 준 해시와 다르면 멈춥니다.
3. `git diff app/assets/mods.lock.json` 으로 버전이 바뀐 모드를 확인합니다.
   «최신판» 이라고 무조건 믿지 말고, 처음 보는 버전·작성자 변경이 있으면 모드린스 페이지를 확인합니다.
4. 커밋하고 런처를 새로 배포합니다. **잠금 파일을 바꾸지 않으면 `mods.json` 만 고쳐도 새 런처에는 반영되지 않습니다.**

## 남은 위험

- 1.0.20 이하 런처는 여전히 `FISH_MOD_LIST/main/mods.json` 을 실시간으로 읽습니다.
  유저가 새 런처로 넘어올 때까지 그 저장소는 계속 공격 경로입니다. 보호 규칙과 2단계 인증을 켜 두세요.
- 런처 자동 업데이트 자체가 서명되지 않았습니다. (Windows 설치 파일 코드서명 없음, macOS 업데이터는 quarantine 을 지움)
  GitHub 계정·토큰이 털리면 업데이트로 악성 런처를 내보낼 수 있습니다. 코드서명 또는 별도 서명 키로 업데이트를 검증하는 작업이 남아 있습니다.
