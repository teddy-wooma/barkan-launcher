실제 HUD 배칭 구조 진단 - 최종 FPS/메모리 비교와 분리

상태: 세 BG 실행 성공. 동일 glyph/index 수에서 실제 mesh/draw 회복 확인.
범위: diagnostic_only_not_final_FPS. background 계측이므로 이 실행의 FPS를 최종 성능값으로 쓰지 않는다.

BG-OFF-1                     2          7              5                1
BG-GLOBAL-ON-1               53         58             56               52

위 값은 모든 HUD 표본 frame에서 고정이었다. 세 실행 모두 glyph151,
font index1812, 전체 GUI index1938로 동일했다. 이전 global은 텍스트 저장을
여러 GPU page에 흩어 놓았고 공식 GUI 정렬 뒤에도 mesh/draw가 늘었다.
small-text 후보는 원본 raw 셀 높이22/폭1~32인 bitmap을 별도 owner pool에 두어
이 장면의 draw 및 texture bind 횟수를 OFF 수준으로 회복했다.

해당 BG의 shared GPU 관측
  oldglobal: shared RGBA5장 / 1,310,720B
  small-text: shared RGBA6장 / 1,572,864B
    bootstrap main1 + 일반 main4 + small-text1
  한 RGBA256x256 page(262,144B)를 더 써서 배칭을 회복했다.
  이 수치는 shared-only다. fallback RED 등 TextureManager 전체 unique
  FontTexture 저장량을 뜻하지 않으며 최종 cold/reload별 전체 값과 다를 수 있다.

진단 agent draw 범위
  GlCommandEncoder.drawFromBuffers의 실제 여섯 분기(직접 GL 네 분기와
  GlStateManager 두 wrapper)를 포함한다. 제출 glyph만 센 수치가 아니다.
  native GUI bind는 _bindTexture의 2D wrapper 및 cache miss GL 호출 범위다.
